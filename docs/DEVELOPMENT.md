# Среда разработки простыми словами

## Что такое проект

Проект — это папка с исходным кодом и описанием того, как собрать из него приложение. Главный файл `Package.swift` играет роль инструкции для компьютера: какие части проекта существуют и как они связаны.

## Что уже установлено

- **Xcode 27.0** — полный набор инструментов Apple для приложений macOS.
- **Swift 6.4** — язык и компилятор, которым собирается приложение.
- **macOS SDK 27.0** — набор системных деталей, доступных приложению.
- **Git** — история изменений проекта. Если что-то сломается, можно увидеть, что именно менялось.

Этого достаточно для текущего приложения. Рабочий стол складывает Metal-рендер
из кадров ScreenCaptureKit; системный экран блокировки использует отдельный
живой backdrop через WindowServer и Core Animation. Мини-превью использует
Metal при подключённом рабочем столе и Core Image для демонстрационной сцены.

## Основные команды

```bash
./scripts/run.sh
```

Собирает привычный пакет `MacDuo.app` и запускает его. Внутри пакета лежат исполняемый файл и паспорт приложения `Info.plist`; macOS использует этот паспорт, чтобы узнавать приложение между запусками.

```bash
./scripts/test.sh
```

Собирает всё приложение и проверяет математику анимации. Это небольшой автоматический чек-лист: закрытый угол должен давать закрытое состояние, открытый — открытое.

```bash
./scripts/sensor-check.sh
```

Отдельно проверяет датчик крышки и печатает три сырых чтения угла. Эта команда нужна для диагностики совместимости конкретного MacBook.

```bash
./scripts/display-check.sh
```

Показывает подключённые экраны и отдельно отмечает встроенный, внешний и основной. Ничего не меняет в расположении и настройках мониторов.

```bash
git status
```

Показывает, какие файлы изменились. Ничего не удаляет и не отправляет в интернет.

## Структура папок

```text
Sources/MacDuo/       само приложение и его интерфейс
Sources/MacDuoCore/   математика эффекта
Sources/MacDuoChecks/ автоматические проверки
docs/                 план и объяснения
scripts/              готовые команды запуска и проверки
```

## Почему используются скрипты

`run.sh`, `test.sh` и `sensor-check.sh` явно выбирают Xcode из `/Applications/Xcode.app`. Благодаря этому проект не переключится случайно на устаревшие Command Line Tools. Технический кэш хранится внутри проекта и не засоряет другие папки.

## Где менять эффект

Эталон — принятый пользователем локскрин. Оба полноэкранных режима используют:

- `Sources/MacDuo/FoldOverlaySurface.swift` — живое окно, плавность и завершение;
- `Sources/MacDuo/ProjectedBackdropView.swift` — живое содержимое под окном;
- `Sources/MacDuo/BlurRevealMask.swift` — плавный переход от резкого изображения к блюру;
- `Sources/MacDuo/FoldProjectionMesh.swift` — прежняя сетка, доступная только в диагностике;
- `Sources/MacDuo/FoldMaskView.swift` — растворение тёмного верхнего края;
- `Sources/MacDuoCore/FoldGlassGeometry.swift` — прямая и обратная проекция стекла;
- `Sources/MacDuoCore/FoldAppearance.swift` — радиус блюра, инерция и прозрачность;
- `Sources/MacDuoCore/EffectTuning.swift` — общие настройки и сохранённые пресеты.

`OverlayController` и `LockScreenOverlayController` отвечают за момент показа
в своём контексте. Рисовать новый эффект отдельно в этих контроллерах не нужно.
`FoldPreviewSurface` использует ту же маску и параметры; уменьшенную картинку
размывает Core Image, потому что фон внутри окна нельзя размывать через WindowServer.

Для нативных проверок после сборки:

```bash
.build/MacDuo.app/Contents/MacOS/MacDuo --live-blur-smoke-test
.build/MacDuo.app/Contents/MacOS/MacDuo --blur-coverage-check
.build/MacDuo.app/Contents/MacOS/MacDuo --perspective-check
```

Первая проверка показывает собственные окна и проверяет оба режима, разворот
анимации, повторный показ, завершение и независимое освобождение зависшего слоя.
Вторая требует уже выданного разрешения на запись экрана и сравнивает только
собственные тестовые окна на разблокированном Mac. Она проверяет заполнение блюром,
плавность края и совпадение двух режимов на углах 80°, 60° и 40°. Настоящий локскрин
не снимается; проверка реального сна и входа остаётся отдельным ручным сценарием.
Третья проверка отслеживает четыре цветные метки внутри собственной сетки при
закрытии и раскрытии. Метки также перемещаются при неподвижном угле, чтобы проверить
обновление живого фона. Одно движение маски эту проверку не проходит.
